# 2026-10-24 — Build di WERA con JDK 25 (pom + JAXB)

## Obiettivo
Compilare WERA con JDK 25, come gestit, senza perdere la compatibilita con Java 8.
Richiesta dell'operatore (via sessione Jenkins), modifica a `pom.xml` e a un file Java
autorizzata esplicitamente dall'operatore in chat: deroga alle regole "DA NON TOCCARE".
Scelta dell'operatore: `<release>8</release>`.

## File toccati
- `pom.xml`
  - `maven-compiler-plugin` 3.1 -> 3.13.0, `source/target 1.7` (rifiutati da javac 25) ->
    `<release>8</release>`; `<encoding>Cp1252</encoding>` (sorgenti: 146 ISO-8859-1, 7 Cp1252,
    6 UTF-8, 462 ASCII; da Java 18 javac usa UTF-8 per default e dava centinaia di errori;
    Cp1252 riproduce la build storica su Windows).
  - JAXB (rimosso dal JDK da Java 11, usato da `importbo.*`, `FunctionFileUploadDatiRilevatori`,
    `JobImportAutomatico`): `javax.xml.bind:jaxb-api` 2.3.1 + `org.glassfish.jaxb:jaxb-runtime`
    2.3.9, namespace javax (Tomcat 9).
  - Una sola `javax.activation`: `com.sun.activation:jakarta.activation` 1.2.2 esplicita,
    escluse `activation` 1.1 (da javax.mail) e `javax.activation-api` (da jaxb-api).
  - `xerces:xercesImpl` 2.2.1 escluso da `fop` 0.20.5: si registrava come SAXParserFactory e non
    supporta `FEATURE_SECURE_PROCESSING`, cosi l'unmarshal JAXB falliva (verificato: anche con il
    WAR in esercizio su Java 8 e il JAXB interno del JDK 8). Senza, si usa il parser del JDK.
- `src/main/java/net/project/misc/hash.java` — `sun.misc.BASE64Encoder` (rimosso dal JDK 9) ->
  `java.util.Base64.getEncoder().encodeToString`. Output identico per digest MD5/SHA-1 (il
  vecchio encoder andava a capo solo oltre 76 caratteri). Classe senza chiamanti.
- `CLAUDE.md`, `QA.md`.

## Cosa NON e stato toccato
Altro codice Java, `config.cfg`, template, CSS, script di deploy.

## Rischi / punti aperti
- **Jenkins**: il job "wera2026 PROD" usa ancora il tool JDK8 (Temurin 8): con il nuovo pom
  compila comunque, ma va riportato alla JDK di sistema (togliere `<jdk>JDK8</jdk>` dal
  config.xml del job, backup + restart di Jenkins) con l'ok dell'operatore; poi temurin-8-jdk su
  .115 si puo disinstallare. Verificare che il Maven di Jenkins sia >= 3.6.3.
- **Maven dell'operatore**: lo script esterno `deploy_wera_patch.bat` chiama `mvn` dal PATH:
  deve essere >= 3.6.3.
- Il mittente delle mail di reset resta `ResetPassword.Mail.Address.From` (indirizzo reale nel
  config): non e `mail.from`. Con il mailcatcher non esce comunque nulla.
- Upload dati rilevatori XML da GUI non provato con un file reale (solo JAXB isolato): da fare al
  primo deploy.
